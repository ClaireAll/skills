# 源码交互说明

把指定范围内的实际行为整理为可点击的 HTML 流程图。交付重点是“用户做什么、看到什么、接下来发生什么”，不是源码导读或页面视觉复刻。

## 范围与协作

- 开始前确定源码目录、目标页面或本轮子模块、已有文档。沿用已明确的选择；关键范围缺失时只问缺失项，输出目录按「产物管理」确定。用户要求先询问时，先对齐范围再生成。
- 默认逐块推进：主页与权限 → 卡片 → 配置面板 → 各动作；顺序依产品调整。本轮只完成用户指定块，不因“补齐”擅自生成整个产品。
- **必用配合技能：** 源码与文档核对使用 `require-understand`；HTML 图表使用 `archify`。先读当前任务适用的技能入口，只读取当前流程需要的参考文件。若不可用，说明限制，复用现有 HTML 或原生 HTML/SVG，不声称通过缺失工具的验证。
- 只读指定业务源码。为确定实际行为可追踪被调用的直接依赖和文案，不扫描无关旧版分支；若必须实质扩展范围，先说明并询问。
- 分析、完整性询问是只读任务；用户要求新增或更新文档后才写文档。不要顺手修产品代码、提交或发布。

## 从代码到动作清单

先枚举入口、控件、事件处理、校验、异步回调、显隐条件、文案和必要的共用组件，再沿实际调用链逐项核对。共用控件要检查调用参数造成的差异，不能用一种通知的接收人规则代替所有通知。

以本轮指定版本的当前源码为行为依据。源码与旧文档不一致时，按已核实的源码行为编写，并在核对数据中记录差异；差异是否符合产品预期标为待确认，不静默沿用旧文档。源码不足以确定的后端、配置或运行环境行为保留待确认，不推断为已实现。

每项动作保留以下核对字段，可放在 HTML 内不自动展示的结构化数据中：

| 字段 | 记录内容 |
| --- | --- |
| 定位 | 章节、控件、入口位置；源码文件与符号；对应图节点或规则表 |
| 前置状态 | 默认值、已有值、身份、环境、版本、开关、加载或缓存状态 |
| 用户动作 | 点击、悬浮、输入、选择、取消等具体动作 |
| 过程与结果 | 即时变化、请求期间、返回后、异常、恢复和持久化边界 |
| 页面文案 | 实际显示字符串及变量替换；tooltip、错误和成功提示 |
| 核对状态 | 已核对／未核对／待确认／有证据的不适用；注明缺少的依据 |

按控件适用性检查，不把下表每项硬套到不存在的功能：

| 对象 | 必须查清的交互维度 |
| --- | --- |
| 入口与操作 | 具体位置；显示、隐藏、置灰分别由什么条件决定；置灰 tooltip；能进入页面不等于能执行管理操作 |
| 输入与选择 | 初始空值或已有值；输入、搜索、防抖、清空、失焦、回车、重复选择、多选、全选与取消范围；确认和回退 |
| 弹窗与面板 | 打开、关闭、取消、折叠、重新打开；草稿是否保留；外层滚动或外部点击的影响 |
| 异步与层级 | 请求前、loading、返回空或有数据、失败；缓存命中与未命中；搜索后再展开和定位；请求未返回时继续操作 |
| 校验与权限 | 校验时机、顺序、位置；必填、格式、上限；警告还是阻断；标红何时出现和消失；恢复条件 |
| 提交与副作用 | 防重复、忙碌、节流；成功 toast 对应的是任务开始还是完成；保存与执行是否不同；取消能否撤销已发生的外部创建 |

同一条件在入口、配置区、保存、执行阶段可能不同。环境、身份或渠道有多项差异时，用明确条件表，不写“根据环境决定”。数量上限、国际化文案和动态参数从当前源码核实，不能沿用旧稿里的数字。

## 图与详情的内容契约

- 每个可感知动作和状态分支直接进入流程图。详情补充规则与准确文案，不能用一段详情替代尚未画出的加载、异常或再次打开分支。
- 判断节点的边写清条件；无依据的分支标待确认。独立操作不能仅因排列相邻就连成执行顺序。
- 分组后的兄弟动作保持相同梳理粒度：每一种通知、回填、存档都有自己的适用字段入口；内部可复用相同数据，但保留调用差异。
- 页面预览不要求像素复刻，但产品文案必须正确。产品原文正常显示；解释性文字用灰色并加中文括号，表格单元格中的补充说明也遵守。产品原文与解释尽量分开。
- 默认不展示技术元信息、源文件归属说明、上下游计数、复制链接、视觉装饰描述。源码依据留在核对数据中，用户要求证据时再提供。

### 异步分支示例

不是一个“选择位置”节点加大段详情，而是：

```text
输入关键词 → 等待搜索 → 有结果？
  无 → 显示已核实的空结果文案
  有 → 展开结果 → 选中 → 关闭并清空搜索 → 检查祖先缓存
    已加载 → 再次展开可定位
    未加载 → 发起请求 → 再次展开时已返回？
      否 → 显示加载 → 返回后定位
      是 → 定位
```

创建成功、刷新位置树、清除位置错误、加载字段结构是分别查证的阶段。不能根据感受到的延迟推断因果，也不能给源码未定义的失败处理编造 toast。

## 默认阅读交互

以下是本技能的交付默认值；用户明确提出新要求时以新要求为准，不修改通用 `archify` 的默认行为。

- 按章节及独立子流程切换，不默认合并成一张巨型总图。
- 点击节点只更新固定右侧详情，不打开 popup，不自动缩放、居中或平移左图；切换子流程可重置到该图起点。
- 悬浮节点时高亮直接关联线及端点，离开恢复；键盘聚焦提供同等反馈。不要将“交互效果”解释为自动连线动画。
- 默认无自动播放。若用户说“统一动画”但指代不清，先确认触发动作和可见变化。
- 图节点、详情正文、表格和导航字体保持 16px；不靠缩小字体塞入屏幕。图较大时拆成易定位的子流程，阅读区可滚动；不默认为总图平移方案。
- 使用最新确认的布局。用户撤销一次布局改动时只撤销该改动，保留此前确认的内容和交互。

## 两类验收分开报告

1. **内容覆盖：** 对照动作清单检查源码事件与图节点的映射。确认每条适用分支有节点或条件表；查清共用组件差异、完整文案和异步时序。未核对项明确列出，不能算已覆盖。
2. **HTML 行为：** 在真实浏览器检查全部分组、节点详情、悬浮进入/退出、键盘聚焦、重复节点隔离、连线与标签、16px 字号、点击前后图的位置和缩放不变；检查各桌面尺寸和使用到的主题。为新增交互保留一个可重跑检查。

页面检查通过只证明文档可用，不证明源码交互无遗漏，也不证明真实后端业务已执行通过。只有已声明范围的核对清单关闭后才能说该范围核对完成；仍有缺口时说清已完成部分和未核对项。

修改已有定制 HTML 时先识别真实维护源；旧版 JSON 可能只描述主页，不能直接重新生成并覆盖后续章节。使用实际可运行的检查验证当前 HTML，不将旧规格的校验结果冒充当前完整文档验收。

## 产物管理

- 输出目录优先使用用户指定位置，其次复用本任务已有的仓库外文档目录；均未提供时，默认使用 `D:\Claire\visualizations\interaction-guide\<项目名>\<页面或模块名>` 并告知实际路径，无需仅为目录另行询问。全部生成文件写入该目录，不污染业务仓库。默认更新同一份 HTML，不为每轮产生历史副本。
- HTML 优先自包含。源码核对数据可用惰性 JSON 保存；检查函数可内嵌但只手动调用，不能正常打开就执行检查或改变页面状态。
- 只有用户要求清理时删除历史文件。先列文件、检查引用与用途；合并独有内容并验证后，才移除原文件。保留无关文档；明确区分完整维护源和仅供参考的旧源数据。
- 历史截图、过期验证报告等可再生成副产物优先移入回收站；不得按扩展名批量删除。交付说明删除范围和恢复方式，不在整理后又留下同类副产物。
- 收尾给出当前文档链接、本轮覆盖范围、实际验证结果和待核对项。关闭本次启动的临时浏览器、服务与监听进程，不影响用户原有进程。

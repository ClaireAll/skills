# 读懂功能/交互文档输入(通用规则)

这是一套**可复用的输入读取规则**,被其它 skill 的「读输入」步骤引用(也能单独用于「帮我读懂这份需求材料」)。

**核心边界:本 skill 只负责把各种形态的输入读全、读对、读懂,不规定读完之后怎么用。** 要不要把理解落成中间产物(报告 / 清单 / 直接进入下一步),由**调用方 skill 决定**——本 skill 既不强加,也不禁止。

## 1 · 识别输入形态

输入可能是下面任意一种,或几种混合(例如"功能看这个飞书链接,交互看这个 figma"):

- 飞书文档链接
- Figma 链接
- 本地 md / 其它文件路径
- 用户直接打字的一段功能描述
- 以上的混合

先判明有哪些来源,再逐个读;**别只读第一个就动手**。

## 2 · 各来源的正确读法

### 飞书文档

- 优先使用当前已连接的飞书/Lark 文档 MCP 读取正文，按工具 schema 传 URL；需要时先将 wiki 节点解析成实际文档。不要依赖固定工具前缀或把链接标题当正文；分页响应要读完相关范围。
- 图片影响理解时取原图；支持 `fetch-doc(need_url=true)` 的工具可返回临时下载链接，链接过期就重新获取。`fetch-file` 可能压缩长图、密图，文字不清时不能当成已读；图片 `alt` 或自动摘要也不能替代原图。处理尽量在内存中完成，需落盘时放任务专属的 `D:/Claire/temp` 目录。
- **画板要读取文字、层级和连线关系，缩略图不能证明已读完整。** 仅在遇到飞书画板时加载 [references/feishu-whiteboard.md](references/feishu-whiteboard.md)，按可用能力取节点数据；不要求安装新 CLI。
- 表格单元格图片、内嵌电子表格要用当前可用的资源/表格工具读取；只有占位符或工具无法读取时，记录未读范围及原因。折叠内容优先从文档工具取，不在浏览器中为读取而展开会持久化的折叠标题。
- 工具未加载、连接失败或授权失效时，协助用户连接/续期，保留目标和进度；用户完成后先用 MCP 对原目标做只读验证。权限不足与资源不存在单独说明，不反复要求登录；网页登录成功不等于 MCP 恢复。

### Figma(纪律最严,最容易漏读)

- **必须走 Figma MCP**(`get_design_context` / `get_screenshot` / `get_metadata` / `get_figma_data`)。调用前读取该工具要求的 Figma Skill，并核对当前 schema。
- **禁止用 WebFetch / 裸 HTTP 抓 Figma 网页**当作"已读交互稿"——抓不到稳定节点树和标注,必漏交互覆盖。
- 从 URL 解析 `fileKey`;带 `node-id` 时把 `1-4` 这类格式转成 API 用的 `1:4`。无节点链接的元数据可能只含封面，不能当成整文件；用可用的页面定位能力找到目标，否则向用户要具体页面/画板链接。
- **界面文案与可见状态以截图为主要证据，元数据用于层级、坐标和定位。** 元数据可能缺少组件实例内部文字或因返回上限被截断，不能据此认定没有说明。
- 大画板先用缩略图定位区块，再回到原图按左上角为原点的绝对坐标切片，逐片查看主体及旁注；核对首片包含左上角、边界没有遗漏。不要按中心偏移裁切或将放大的缩略图当原图。临时图片放任务专属的 `D:/Claire/temp` 目录。
- 模糊、遮挡的文字对相应小子树调用 `get_design_context` 核实原文，不为几行文字拉整个文件。隐藏图层、空白渲染或裁切后仍未读到的说明分别登记为未读；仍不清楚的文字标 `【待确认:字迹不清】`，不猜测补全。
- **务必逐个读画板里的「备注」框(name 含「备注」的 FRAME/INSTANCE)和紧贴画板的旁注 TEXT**——入口、置灰/选中、Tooltip、校验时机与文案、toast、复制粘贴规则、标红与报错策略、与 PRD 的冲突点等**验收规则常藏在备注里**,只看组件 demo 会漏。
- **画板旁边的规格卡 / 标注卡是一等需求来源,不是装饰**:任何以说明、规格、注释形式呈现的结构化信息,都要作为验收规则读取;只看画板主体 UI 截图会漏规则。
- 规格卡与多个对象相邻时,必须建立其归属关系;归属不清就标 `【待确认:Figma 标注归属不明】`,不要把旁边的大段标注直接忽略。
- **排版量与色值要抓成设计变量名,不是抄数值**:字号 / 行高 / 控件高度 / 间距 / 圆角 / 各状态色值在设计稿里都由设计变量定义,用 `get_variable_defs` 取变量名。下游断言锚在变量名上 —— 同一个变量在不同主题作用域下取值不同,抄下来的 hex / px 换个主题就不成立。数值只作对照记录,并注明是哪个作用域下的取值。
- **Figma 图层/节点编号只用于你内部分析**,把内容映射进下游产物时**一律语义化指称**(如「画板备注:导出与异常」),**禁止把 `210:31749`、「备注315」这类编号写进下游产物正文**(用户 URL 里原生的 `node-id=` 参数除外)。
- MCP 真的不可用(多次失败 / 未鉴权 / 无文件权限)时:在对话写明原因和已试步骤,相关交互内容标 `【待确认:Figma MCP 不可用】`,**禁止**用"未能自动读取 Figma"草草收尾。

### 本地 md / 其它文件

- 用 `Read` 读取路径指向的文件。

### 一段文字描述

- 用户直接打字的需求,直接用,不用去找文件。

## 3 · 混合来源对齐

- 把**所有**给到的来源都读完再动手,别漏掉其中一个。
- 来源之间冲突时，检查用户已确认的决定、适用范围和生效依据；不能仅凭更新时间、格式或现有实现选定规则。没有裁决依据的点标 `【待确认】`，列明冲突双方及影响。

用户明确提供的参考资料要逐一记录真实读取状态。未读到的正文或关键图示不能用转述、记忆或猜测补齐；说明未读范围及原因，只推进不依赖它的部分。

## 4 · 读懂什么(读取重点)

读的时候主动把这些抓全,作为"读到位"的检查项,便于调用方直接使用:

- 功能点与业务规则、状态流转、权限规则
- 交互行为:入口、置灰/选中态、校验时机与文案、toast、标红与报错、显隐流转、**状态之间能否叠加**(报错的元素被选中时是什么表现、禁用的元素被悬浮时是什么表现);材料把状态写成并排的几项时,默认它们互斥是常见误读,读不出叠加口径就标 `【待确认】`
- **视觉与排版规格**,分两级抓:**元素级** —— 本次新增 / 改造的标签、徽标、图标,逐状态的底色 / 边框 / 文字色 / 圆角 / 内边距;**容器级** —— 承载它们的面板、弹窗、抽屉、折叠区**自身**的内容区字号、配置行的标签与控件如何对齐、控件高度、页脚按钮尺寸、行间距。**容器级最容易整档漏读**:需求文档只说面板里有哪些配置项,设计稿只呈现排好版的成品,两边都不会把「这个面板用小一号字、按钮用小尺寸」写成一句话,得从稿子上量、从设计变量里读
- 数据/字段线索:涉及的字段类型、数据来源、空值/异常/边界提示
- 初始化与状态规则:默认、初始、状态差异、兼容与降级口径
- 约束 / 硬规则 / 特殊要求
- 是否声明了升级兼容、移动端
- **待确认点与矛盾点**(含需求里的 Q 编号、与 PRD 冲突处)

## 5 · 信息不足就先问

如果关键交互、规则或边界在所有来源里都说不清，默认**一次问用户一个具体问题**，而不是猜着补。用户明确要求批量提问时，遵循入口 Skill 的澄清规则，只合并前置条件已明确、彼此独立的问题。把理解建立在读到的内容上，读不到的就标 `【待确认】`，别硬编。

# 前端源码检查

由 claire-test 在审查指定前端文件或待提交改动时读取；纯用例生成和已有表格整理不加载本模块。复用 source-audit 的范围、证据、反证及中文输出，不新增第二份报告。仅有源码、没有需求时，检查可证明的代码问题并注明规格依据缺口。

先读取三个检查表：[代码质量](references/code-quality.md)、[性能](references/performance.md)、[业务逻辑](references/business-logic.md)。逐项判断是否适用，跟踪相关调用方、状态 Provider、React Flow 数据与 props 引用、样式覆盖及跨包数据流。

## 适用条件与裁决

- 检查表从原本地 frontend-code-review 迁入并原样保留；其中 Dify 节点路径与 workflowStore Provider 规则只在实际结构与调用路径匹配时适用，不能套用到其他项目。历史 issue 链接是排查线索，不证明当前项目存在同一问题。
- classNames、Tailwind 和样式顺序遵守当前仓库已确认的技术栈与约定，不要求迁移样式方案。类名先后不保证覆盖生效，结合实际合并工具和 CSS 规则判断。
- React Flow 规则仅用于实际使用该库的路径；复杂 props 的 memoization 建议须有消费者依赖引用稳定性或实际重复计算的证据，不把所有内联对象自动判为缺陷。
- IsUrgent 是原检查表标签，不直接决定当前问题等级。按可达路径和用户后果定级，区分真实缺陷与可选建议；缺少审查或测试本身不是已存在的业务 bug。

## 执行与输出

1. 读取范围内源码和必要调用方，复用已有需求、状态与比较基准。
2. 对适用规则收集实际位置、触发条件和影响证据，排除被上游约束阻止的候选。
3. 合并重复问题，按 source-audit 的中文格式给出位置、原因、最小修改建议和待验证步骤；无发现仅表示当前范围未发现问题。

保持只读，不修代码、不安装依赖、不启动页面；不沿用原独立入口的英文固定模板、最多十条截断或自动询问修复。发现问题不构成修改授权。

## 来源

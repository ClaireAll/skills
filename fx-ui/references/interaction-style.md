# FX UI Interaction Style

这是 `fx-ui` 的通用规则摘要。只读取当前流程相关章节。Tooltip、Title、校验、搜索、禁用、说明图标、Pop 尺寸和 Loading 的细化规则分别见同目录专用参考文件；专用规则优先。没有明确证据的精确颜色、尺寸、间距和动画参数不得自行补充。

## 多层级结构

- 第一层使用 `Tab-Cube`，可横向或纵向。
- 纵向第一层只在 Tab 中显示图标，标题放在选中内容区域的列表中，不使用纵排文字。
- 第二层可选用 `Tab-Default (Line)`；第一层横向时第二层纵向，第一层纵向时第二层横向。
- 第三层使用 `Tab-Segment`，用于局部配置切换，层级弱于前两层。
- 配置项较多时按主题使用 `Collapse` 聚合。是否默认展开、是否手风琴、是否保存展开状态由模块需求决定。
- 如果折叠能力本身可切换，使用 `Switch`。

## Tooltip

Tooltip 的对象类型、状态、延时和定位以 `tooltip-validation.md` 为准；本节只保留通用原则。

- 截断文本使用 Title 或浏览器默认提示，完整值应可查看。
- 列表中从一个已出现的 Title 移到下一个截断项时，可以直接展示下一个，不重复等待完整延迟；列表 Tooltip 延时为 `0.5s`，其他 hover 提示默认为 `0.1s`。
- 按钮 Tooltip 用于解释按钮名称，以及禁用或错误原因。
- 默认和禁用态使用深色 Tooltip、三角箭头，默认显示在组件下方并处理碰撞；错误态使用错误色和三角箭头。
- 按钮 Tooltip 采用项目默认短延迟；离开按钮命中区和 Tooltip 后消失，允许移动到 Tooltip 本身。
- Tooltip 不占布局空间；默认优先显示在触发器下方，空间不足时显示在上方，距离触发器约定为 4px 时才可作为已有规则使用。
- 跟随容器时不显示箭头，跟随具体内容时显示箭头。一个容器不要同时触发多个 Tooltip 风格。
- 输入框错误使用红色边框和黑色内容；校验 Tooltip 按规则显示，错误 Tooltip 通常在 hover 时显示。
- 胶囊只在具体错误元素上标红，不要整块容器一起标红。

## 文本输入与字段报错

- 复用 FD Input 的浮层校验提示。
- 输入失效后在 blur 时校验；需要恢复时恢复上一次合法值，不在输入过程中擅自清空用户正在输入的内容。
- 常用文案模板：`{字段名}不能为空`、`{字段名}已存在`、`请输入 100 个以内字符`、`请输入单个字符`。其他错误沿用输入框提示模板。
- 字段报错第一行优先写明错误原因。
- 字段使用展示别名时，必要时同时展示展示名和来源字段名；来源不是当前表时注明来源表，帮助用户定位修复位置。
- 缺失字段的单选、多选、禁用态和 Tooltip 行为属于专项规则，只有当前流程确实使用该场景时才套用。

## 搜索

前端本地搜索的完整规则以 `search.md` 为准；远端搜索不在本 skill 的前端匹配审查范围内。

- 纯前端筛选实时搜索；会触发后端请求的搜索直接跳过前端匹配规范审查。
- 匹配结果高亮；默认不区分大小写，并支持拼音首字母，除非当前模块有明确例外。
- 文档对部分大小写细节仍标记待确认，不要继续推断更细规则。

## 隐藏、禁用与权限

完整判断顺序和复杂可用性反馈以 `disabled-actions.md` 为准。

- 当前上下文根本不存在的能力：隐藏。
- 固定权限永远不可用：隐藏，不展示无效菜单项。
- 动态权限、临时限制或条件暂不满足，但结构仍有意义：禁用并提供 hover Tooltip。
- 尚未选择、输入或完成前置操作：禁用并解释原因。
- 原因复杂或需要后端判断时，保留可点击状态，在点击后加载并反馈原因。
- 不要用点击 Toast 代替已经明确的禁用态 Tooltip。

## 导出

- 点击导出后显示加载提示：`数据导出准备中，稍后自动下载`。
- 加载提示最长自动关闭时间为 5 秒；结果在此之前完成则关闭加载提示并给出结果，之后完成则直接给出结果。
- 成功触发浏览器下载；失败提示：`「文件名」导出失败，请重试`。
- 导出期间按钮禁用、图标显示 loading，Tooltip 为 `正在导出...`。
- 导出不阻塞其他操作；多个文件可并行，多个 Toast 垂直堆叠；切换页面时 Toast 仍按产品约定保留。
- 下载文件名使用资源名称。

## Popconfirm

- 轻量、可逆、频繁操作使用 `Popconfirm`。
- 通用通知、警告或严重且不可逆操作使用 `Alert`。
- 默认不增加多余标题；已有明确场景时才补标题。
- 确认按钮尽量使用具体动作词，不用含义模糊的“确定”。

## 列表批量选择

- 普通点击切换单个 Checkbox，并更新范围选择锚点。
- 普通点击后 Shift+点击选择锚点与目标之间的完整范围。
- 范围内状态统一为第一次普通点击形成的状态，范围内原有不同选中状态会被覆盖，范围外不变。
- 每次 Shift+点击重新计算范围；没有详细规则时不要自行实现 Ctrl 行为。

## Loading、InputNumber 与 Select

- 加载使用 FD `Spin`；是否需要文字提示取决于具体场景，来源未确认时标记待确认，不为每个 loading 追加文字。
- InputNumber 输入非法内容时先保留可见输入，blur 后按控件规则提示并恢复上一次合法值或默认值。
- 不要在输入过程中自动清空、四舍五入或静默改写用户输入；小数、孤立负号、孤立小数点等中间态要区分处理。
- 越界提示应包含范围，例如 `请输入 1-10 的整数`；前导零可归一化为正常显示值。
- 允许清空与“不可为空”的处理依赖字段场景；初始无默认值时不要立即报错。
- Select 的边框和状态复用 FD 视觉，至少覆盖默认、hover、点击、错误默认、错误 hover、错误点击。
- 精确颜色和尺寸以现有 FD token 或明确设计稿为准，不从文字规则臆造。

## 引导与其他设计点

- 固定文案适合长期、轻量、可忽略的规则提示；可关闭时在浏览器保存关闭状态。
- Popover 适合针对具体控件的上下文说明，按 hover 或系统触发，并准确指向目标。
- 空状态、loading、动态图片、强调效果、Tour、弹窗引导属于引导类别；当前来源未提供完整正文时只做覆盖检查，不补具体样式。
- 列表拖拽使用 FD 拖拽设计，在目标位置显示占位提示。
- 解释性说明使用灰色图标；具体图标细节以项目现有组件为准。
- 弹层尺寸和部分零散设计点的来源正文不完整，统一列为待确认。

## 来源与证据等级

- **强规则**：页面正文明确说明，且没有被后续讨论或状态标记推翻。
- **补充规则**：子页面、讨论页或专项确认页提供的场景规则，只在对应场景使用。
- **待确认**：页面只有标题、图片未能提取、明确写有待确认，或不同页面互相冲突。

审查时必须标明证据等级。对“文档期望”和“源码实际行为”不一致的情况，先报告差异，不直接把源码改成某个猜测答案。
